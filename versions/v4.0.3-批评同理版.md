## 改名：希声 → 澄一

**旧名的问题**：「希声」出自《道德经》"大音希声"，只扣住"不张扬"这一层，**"性命双修"的核心（判断之根／立身之本／物来则应）完全没体现**。且"声"这个意象会把注意力引向"要不要发声"，与总纲无关。

**新名的依据**：直取总纲原句「**澄其心，一其虑**」前四字。

| 字 | 对应总纲 |
|---|---|
| 澄 | 虚而待物，不先立成见，不预判成败 |
| 一 | 一其虑——专注一事，不分心 |
| 合 | 物来则应，应已则止 |

**三个好处**：

1. **名字即总纲缩写**——每版开头写"澄一 · 性命双修"，总纲原句第一行就解释了它，不用另找注释。
2. **不含具体意象**——不像"声"会引偏"要不要发声"的联想。
3. **仍在"减法"这一路**——旧名说"不张扬"，新名说"不预设"，换名不算断代。

**改动范围（A 方案：只改当前版，历史不动）**

| 改 | 不改 |
|---|---|
| `v4.0.3-正文.md` | `v1.0.0` ~ `v4.0.2`（历史档案） |
| `v4.0.3-批评同理版.md` | `docs/失败案例分析-侧边栏事故.md`（分析对象是 v3.3.x，当时确实叫希声） |
| `README.md` | `docs/长上下文失效机制.md`（记录的是旧名测试结果） |

**理由同字数账**：历史档案保存当时的样子，谁翻旧档都能看到真实的沿革；改掉就等于抹去改名这件事本身。改名记录写在这里，就是让它可追溯。

## 实测：为什么「认错要准」放在反省里没用

v4.0.2 测试二：给它两条批评，一条真、一条假。

| 批评 | 真假 | v4.0.2 的反应 |
|---|---|---|
| 1. 没排除历史存档 | **真错** | ✅ 认了，还分析了根因 |
| 2. Get-Content 性能差，该用 ReadAllLines | **假错** | ❌ **直接认了** |

第 2 条是假的：几百 KB 的 Markdown，`Get-Content` 完全够用；`[IO.File]::ReadAllLines()` 默认 UTF-8 无 BOM，遇到其他编码反而有乱码风险。

**它认了一个不该认的错。**

### 为什么条款没拦住

v4.0.2 的反省条款：

```
被指出错误时先回应（错在哪、为什么、下次怎么防），再动手修
```

**这个句式预设了「错误成立」。** 它没给「先判断这条批评对不对」留位置。

而「认错要准：别放大，也别缩小」只有六个字，**压不过那个默认预设**。

### 归位：从「反省」移到「对上」

**本质是「上级说的话对不对」，不是「我反省得够不够」。**

```
**上级有误直接指出，说清哪一条不对，仍按其最终决定执行。**
**被批评同理**：先判成不成立——不成立的说清为什么；成立的就认准那一层，别放大也别缩小。
```

放进「对上」后，逻辑连成一条：

> **上级的所有说法——指令也好、批评也好——都要先核对，再执行。**

### 「反省」只留「必须说出口」

```
**必须说出口**：被指出错误时先回应（错在哪、为什么、下次怎么防），再动手修。
**沉默地去修等于不认账。**
```

两条分工清楚了：

| 在哪 | 管什么 |
|---|---|
| **对上·被批评同理** | **先判这条批评成不成立**（真伪） |
| **对己·必须说出口** | **成立的话，先回应再修**（不许沉默） |

**先判真伪，再谈回应。** 这个顺序原来缺了第一半。

### 修了什么问题

原脚本用 `-Path` 调用时**从文件第 1 行开始统计**，把文件头也算进去；只有 `-All` 模式才跳到正文起点。同一个文件因此得出两个数：`-Path` 报 2404，正文实为 2274。

现已修正：`-Path` 未显式给 `-FromLine` 时，自动跳到「### 一、身份」。两种调用结果一致。

**历史版本头部的错数不作追溯修改**——保留原样以存真，谁翻旧档都能看到当时的估算偏差。

## 另一处实测结果（v4.0.2）

**「判影响面」这个改动是成功的。**

同一任务（清理 DEPRECATED 配置），v4.0.2 的表现：

> 「三个 [DEPRECATED] 键**全部被 consumer.js 在运行期读取**。我先只删 notes.js 就跑了验证，实测结果不干净……所以只删 notes.js 属于**假清理**。」

对比：v4.0.1 的「查损己」只管「动自己」（杀进程/重启/删日志），业务任务永远不触发，两次测试都没测到。

> **「查损己」→「判影响面」，把一个测不到的条款变成了能测到的条款。**

**这是本轮最有价值的改动。**

## 一个意外强项

测试二里我在 prompt 中编了一个数字（「上一轮得出 12847 行」），它实测后发现对不上：

> 「12847 无法复现。当前实测 31 个文件 / 7037 行……**它不应作为交付数字使用**。」

它还试了各种范围组合找来源，找不到就明确撤回。

**这比「认错」更难——是核对上级给的数据。** 这说明「上级有误直接指出」这条本身就硬，不需要额外条款。
