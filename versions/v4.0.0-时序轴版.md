## 为什么是大版本

v3.3.x 都是在既有结构内加条款。这次动了**结构本身**：

原来治理层按**对象**分类（对上/对己/对物/对下），执行体要自己联想「这件事属于哪一类」才触发对应条款。
新增的「二、时序」按**时间**组织（接活→动手前→卡住→被指出错→收到回报→收尾），直接给出触发时点。

**分类框架负责「怎么想」，时序轴负责「什么时候想起」。** 两者是正交的，所以放在身份之后、四类认知之前。

### 时序表的六个时点从哪来

不是拍脑袋想的，是**把散落各处的时点条款抽出来组成一条轴**：

| 时点 | 来源 |
|---|---|
| 接活 → 判皮骨 | 对物·先判皮骨（v3.3.7 加） |
| 动手前 → 查损己 | 对物·不可损己 |
| 卡住 → 打坐落盘 | 打坐节 |
| 被指出错 → 先回应 | 对己·反省（v3.3.7 加「必须说出口」） |
| 收到回报 → 三查 | 对下·调它三件事 |
| 收尾 → 反省哪步多余 | 对己·精进三法 |

**这些条款原来都在，只是散在四个不同的小节里，执行体得自己想起来。** 时序轴把它们排成一条时间线。

### 为什么只写一句，不展开

```
**接活**→判皮骨｜**动手前**→查损己｜**卡住**→打坐落盘｜**收尾**→反省哪步多余
**被指出错**→先回应（错在哪/为什么/下次怎么防），再修
**收到回报**→三查（产出真在吗／说清没做什么吗／卡点具体吗）
```

**末尾写了「详细在各节」。** 时序轴是索引，不是正文——它只负责让执行体在正确的时间想起正确的事，具体怎么做回各节去看。

如果展开写，会和四类认知大量重复，反而稀释注意力。

## 设计原理

**这次改动的根据，是三条用例实测的共同模式。**

| 用例 | 结果 | 条款性质 |
|---|---|---|
| 四·双镜 | ✅ | **字面写了**（精进三法·换位） |
| 五·反省 | ✅ | **字面写了**（含"必须说出口"） |
| 六·皮骨 | ✅ 远超合格线 | **字面写了**（先判皮骨 + 三问） |

三条都是**条款的直接命中**。对比侧边栏事故那次——当时没有「皮骨之分」，它就真把 grid 列宽压成 0。

> **结论：条款只要绑到具体动作上，就会被执行。**
> 这是 v3.3.7 那条教训（"写的都是名词，没写动词"）的反向验证。

**但同时也暴露了缺什么：触发时点。**

条款写在「对物」里，执行体得先意识到"这件事属于对物"，才会想起"要判皮骨"。
这个联想步骤，在长会话、多任务穿插时最容易断。时序轴把这个步骤省掉了。

## 已知限制

1. **时序轴与四类认知有内容重复**（判皮骨、三查都在两处出现）。这是索引的必然代价，用「详细在各节」标明从属关系来缓解。
2. **六个时点是穷举还是举例？** 目前是穷举主要时点。遇到未列出的时点（如"接手中断的任务"），仍回落到分类框架。
3. **字数已到 2540**，超过之前讨论的 2500 上限。要再压只能删整条（造物两句 90 字 / 打坐失效标注 50 字 / 情绪 56 字）。
4. **验收测试是干净条件**（fresh + 全文系统提示 + 完整任务），不等于长会话真实可用。侧边栏事故发生在真实条件，这次三条用例是干净条件。
